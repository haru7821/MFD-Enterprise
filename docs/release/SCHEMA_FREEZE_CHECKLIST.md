| — | — | `knowledge/dataset.json` | ❌ **none** |

### ❌ Open: `knowledge/dataset.json` carries no version field

It has a schema (`datasetSchema`, parsed by `parseDataset`) and it is a committed artefact that every
other artefact cites — `support.sources`, every corpus row and every observation resolve their
`drawingId` against it. It is the only governed artefact without a version.

**Not fixed in this commit**, because adding one is a schema change and this task is documentation
and hardening only. Raised here so the freeze is entered with it known rather than discovered later.
The practical exposure is low today — the file is regenerated by `pnpm dataset:ingest` from the
dataset itself — and the argument for adding one is the same argument that bumped
`KNOWLEDGE_VERSION` twice this week: a shape without a version is a shape nobody can refuse.

## 2 · Optional fields

**Exactly two** `.optional()` fields exist across every schema in the repository, and both are
deliberate:

| Field | Schema | Why optional |
| --- | --- | --- |
| `frequencies` | `knowledgeEntrySchema` | Owner decision D14: `[]` meant *"no observations exist"* and *"this kind never collects frequencies"* at the same time. Optional rather than nullable, because `null` would be a third spelling of the same ambiguity — an **absent key** is the only encoding that says nothing at all. |
| `measuredOnly` | scoring criterion config | Marks a criterion measured and displayed but excluded from the weighted sum. Absent means false. |

`packages/document-model/src/schema.ts` states the governing rule for the document itself:

> *"Nothing here is `.optional()` — only `.nullable()`. A forgotten key and a key meaning 'unknown'
> are different statements."*

### ⚠️ Open: `.optional()` is not the whole optional surface

The two above are the complete list of **zod** `.optional()` calls, and that is a narrower claim
than "the freeze covers every optional field". Counting `?:` on exported TypeScript interfaces under
`packages/*/src` gives **40**, and the one that matters at freeze is `Rejection.detail`
(`packages/ai-local/src/gates.ts:47-69`):

| | |
| --- | --- |
| Shape | 7 optional properties — `ruleId`, `reasonCode`, `expected`, `actual`, `placementIds`, `measured`, `reasonParams` |
| Exposure | public, three routes — `GateOutcome.violations`, `OptimiseResult.blocking`, `RankResult.rejected` |
| Schema | **none** — it is a TypeScript interface, so nothing validates it at a boundary |
| Consumer | `apps/web/src/features/layout/runSolver.ts:166-174`, off `blocking` |
| Tested | **partly** — `gates.test.ts` and `optimise.test.ts` assert `detail` on the first two routes; **no test asserts a non-empty `rejected`** |

This entry first read *"no schema, no test, a UI consumer branching on it"*. Checked clause by
clause, only the first survived: `detail` **is** asserted by tests, on two of its three routes, and
the consumer reads it off `blocking` rather than branching on it at line 88 — that line reads
`rejected.length` and nothing else. Corrected here rather than left standing, since a freeze
checklist that overstates a gap is the same defect as one that hides it.

What remains true is the shape: every property optional, so the type permits `detail: {}`, and the
consumer compensates with `violation.detail.ruleId ?? ''`. An absent `ruleId` renders as an **empty
string** in the panel — unknown presented as a measured value, in the one place the type system
still allows it. Nothing produces such a `Rejection` today; nothing prevents one either.

Not fixed here for the same reason as `dataset.json`: adding a schema is a contract change, and this
commit is documentation. Full statement in [`RELEASE_GATE.md`](RELEASE_GATE.md) §2.2.

✅ **Clear on the zod surface** — both `.optional()` exceptions are outside the document model and
documented at their definition. ⚠️ **Not clear on the interface surface**, as above.

## 3 · Nullable fields

Nullable is the project's way of saying **"unknown"**, and it is used heavily and on purpose: 38
nullable fields in the knowledge schema, 11 in verification, 5 in provenance.

The rule that makes this safe rather than sloppy: **nullable never means zero.** Enforced in
substance by the reason-code system — a measurement that could not be taken produces an `SC-9xx` or
`RC-9xx` code and an explicit *unavailable* entry, never a `0` that scores like a bad result.

Specific nullable contracts worth naming at freeze:

| Field | `null` means | Not |
| --- | --- | --- |
| `ScoreBreakdown.total` | coverage below `minimumCoverage`; no total is offered | a score of zero |
| `distribution` | the drawings printed no figure to distribute | an area of zero |
| `confirmedBy` / `stopConfirmedBy` | nobody has signed | signed by nobody |
| `serviceClearance.<side>` | the manufacturer has not stated one | a clearance of zero |
| `appliedValue` on a rule | no threshold has been supplied (A-1) | a threshold of zero |
| `sha256` on a drawing ref | the reference predates hashing | a hash of zero |

✅ **Clear.**

## 4 · Public contracts unchanged

Package export surface, as declared in each `package.json`:

| Package | Subpath exports |
| ---: | --- |
| `ai-contract` | 2 |
| `ai-local` | 1 |
| `ai-planner` | 2 |
| `cad-engine` | 1 |
| `document-model` | 2 |
| `layout-knowledge` | 2 |
| `object-library` | 2 |
| `report-engine` | 4 |
| `rule-engine` | 2 |

⚠️ **Changed during the audit phase, deliberately and with version bumps** — listed so the freeze
records what moved rather than claiming nothing did:

- `KNOWLEDGE_VERSION` 1 → 2 (D14, `frequencies` omitted) → 3 (D15, `drawings` renamed `plans`).
- `CORPUS_VALIDATION_VERSION` 1 → 2 (`confirmedBy`, `batchComplete`, `stopConfirmedBy`,
  `stopsConfirmed`, `unapplied`).
- `CONFIRMATIONS_VERSION` 1 → 2 (`kind` discriminator, ISO-8601 `at`).
- New exports: `geometryKey`, `collapseByGeometry`, `compareStrategies`, `compareLayouts`,
  `strategyList`, `denseRanks`, `compareCodepoint`, `compareSignatures`, `rowFingerprint`,
  `confirmationFor`, `confirmationsMatching`, `hasFinalConsonant`, `joinKorean`.
- New field on `RankedLayout`: `tied`, `strategies`.
- `RankedLayout.strategies` changed **order** under owner decision D16 — `CANDIDATE_STRATEGIES`
  order rather than alphabetical, matching the sentence the field is the machine-readable form of.
  No version bump: the field is new this phase and appears in no issued artefact.

**Four** of those exports exist **only so a test can reach them** — `collapseByGeometry`,
`strategyList`, `denseRanks` and `compareLayouts`. That is stated rather than disguised: a claim no
test can reach is the thing this project spent the audit removing, and each of these was private
until something load-bearing was found to be unreachable behind it. `compareLayouts` is the newest
and the clearest case — while it was private, D1's null sentinel could be inverted with the whole
suite staying green.

## 5 · Artefact formats documented

| Artefact | Schema | Regenerated by | Byte-stable |
| --- | --- | --- | --- |
| `knowledge/dataset.json` | `datasetSchema` | `pnpm dataset:ingest` | ✅ |
| `knowledge/observations/*.json` | `observationFileSchema` | `pnpm knowledge:extract` | ✅ |
| `knowledge/derived/*.json` | `knowledgeFileSchema` | `pnpm knowledge:build` | ✅ |
| `knowledge/validation/corpus.json` | `corpusValidationSchema` | `pnpm validate:corpus` | ✅ |
| `knowledge/validation/confirmations.json` | `confirmationsSchema` | **hand-authored** — no batch writes it | n/a |
| `knowledge/verification/*.json` | `drawingVerificationSchema` | `pnpm verify:drawing` | ✅ |

`confirmations.json` is the one artefact the product only ever *reads*. That is owner decision D9:
`corpus.json` may be deleted and rebuilt at any time, and the one datum that cannot be regenerated —
a person's signature — lives where no batch can overwrite it.
